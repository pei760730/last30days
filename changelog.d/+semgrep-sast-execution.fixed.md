The advisory Semgrep SAST job now actually scans: it uses the `p/default` ruleset with metrics off (the previous `--config=auto` was rejected by Semgrep and exited 2 while `continue-on-error` kept the job green), reports findings without blocking, and fails visibly when the scan does not complete. Finding file names and rule ids are treated as data: workflow commands are stopped while Semgrep and the finding listing print, and the job summary shows them escaped as code, so a crafted file name cannot forge annotations or summary content.
