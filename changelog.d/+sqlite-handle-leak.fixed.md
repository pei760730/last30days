Library index connections are now always closed. `with sqlite3.connect(...) as conn` only ends the transaction, so `.last30days-library.db` (and the research store it reads alongside) stayed open after every run — a silent file-descriptor leak on POSIX, and on Windows a `WinError 32` that broke temporary-directory cleanup for any caller saving into one. The Chromium cookie reader also closes its temp-copy connection in a `finally`, so a mid-query failure no longer leaves the decrypted-cookie copy undeletable on disk.
